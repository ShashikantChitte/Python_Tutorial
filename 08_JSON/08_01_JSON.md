**JSON** (JavaScript Object Notation) is the standard text format for exchanging data between programs: web APIs, config files, logs and databases all speak it. Python reads and writes JSON with the built-in `json` module, so nothing needs to be installed, except for the optional validation section, which uses `pydantic` and `jsonschema`:


## Core Functions of the `json` Module

The functions come in pairs: the ones ending in **`s`** work with **s**trings in memory, the others work with **file** objects.

| Function | Direction | Input | Output |
|----------|-----------|-------|--------|
| `json.loads()` | JSON → Python | JSON-formatted string | Python object (`dict`, `list`, …) |
| `json.dumps()` | Python → JSON | Python object | JSON-formatted string |
| `json.load()` | JSON → Python | Open file object | Python object |
| `json.dump()` | Python → JSON | Python object **and** file object | Writes directly to the file |

> 💡 Memory trick: *loading* means reading JSON **into** Python, *dumping* means writing Python **out** as JSON. No `s` means a file, an `s` means a string.

## Parsing & Pretty-Printing Strings

`json.loads()` turns a JSON string into a Python object. `json.dumps()` turns it back, and these options control how the text looks:

| Option | Effect |
|--------|--------|
| `indent=4` | Pretty-print with 4 spaces per level (default: one compact line) |
| `sort_keys=True` | Sort object keys alphabetically, giving a stable output for diffs and tests |
| `ensure_ascii=False` | Keep non-ASCII characters (`मुंबई`, `é`) instead of escaping them as `\uXXXX` |
| `separators=(",", ":")` | Most compact output, with no spaces (useful for network payloads) |

```python
import json

raw_str = '{"name": "Aarav", "age": 28, "active": true}'

user = json.loads(raw_str)                      # JSON string -> dict
print(type(user).__name__, "->", user["name"])
print("active is", user["active"], "(a real Python bool)")

print("\n--- Pretty-printed and sorted ---")
print(json.dumps(user, indent=4, sort_keys=True))

print("\n--- Compact ---")
print(json.dumps(user, separators=(",", ":")))

print("\n--- ensure_ascii ---")
city = {"city": "मुंबई"}
print(json.dumps(city))
print(json.dumps(city, ensure_ascii=False))
```

**Output:**

```text
dict -> Aarav
active is True (a real Python bool)

--- Pretty-printed and sorted ---
{
    "active": true,
    "age": 28,
    "name": "Aarav"
}

--- Compact ---
{"name":"Aarav","age":28,"active":true}

--- ensure_ascii ---
{"city": "\u092e\u0941\u0902\u092c\u0908"}
{"city": "मुंबई"}
```

## Reading & Writing JSON Files

Use `json.dump()` / `json.load()` with a file object. Always pass `encoding="utf-8"` (JSON is UTF-8 by specification), and use `ensure_ascii=False` when writing so non-English text stays readable in the file.

```python
import os
import tempfile

workspace = tempfile.mkdtemp()                      # temporary folder for all examples
path = lambda name: os.path.join(workspace, name)   # build a path inside it

data = {"city": "Mumbai", "skills": ["Python", "SQL"], "verified": True}

with open(path("profile.json"), "w", encoding="utf-8") as f:
    json.dump(data, f, indent=4, ensure_ascii=False)

print("--- What is stored on disk ---")
with open(path("profile.json"), "r", encoding="utf-8") as f:
    print(f.read())

with open(path("profile.json"), "r", encoding="utf-8") as f:
    loaded_data = json.load(f)

print("\n--- Loaded back ---")
print(loaded_data)
print("Same data as the original?", loaded_data == data)
```

**Output:**

```text
--- What is stored on disk ---
{
    "city": "Mumbai",
    "skills": [
        "Python",
        "SQL"
    ],
    "verified": true
}

--- Loaded back ---
{'city': 'Mumbai', 'skills': ['Python', 'SQL'], 'verified': True}
Same data as the original? True
```

## Data Type Conversion

JSON has only six value types, and each maps to a Python type:

| Python Type | JSON Type | Notes |
|-------------|-----------|-------|
| `dict` | Object `{}` | Keys are converted to double-quoted **strings** |
| `list`, `tuple` | Array `[]` | Tuples become JSON arrays (and load back as **lists**) |
| `str` | String `""` | Always enclosed in **double** quotes |
| `int`, `float` | Number | Standard numeric representation |
| `True`, `False` | `true`, `false` | Converted to lowercase booleans |
| `None` | `null` | Mapped to JSON `null` |

Because the mapping is not perfectly one-to-one, a **round trip** can change your data:

```python
original = {1: "int key", "pair": (10, 20), "nothing": None, "flag": True}

text = json.dumps(original)
print("JSON text:", text)

restored = json.loads(text)
print("Restored :", restored)
print("Equal to the original?", restored == original)
print("\nint key 1 became the string key '1'; the tuple became a list.")
```

**Output:**

```text
JSON text: {"1": "int key", "pair": [10, 20], "nothing": null, "flag": true}
Restored : {'1': 'int key', 'pair': [10, 20], 'nothing': None, 'flag': True}
Equal to the original? False

int key 1 became the string key '1'; the tuple became a list.
```

## Serializing & Deserializing Custom Classes (`default` & `object_hook`)

`json.dumps()` only understands the six types above. Anything else, such as `datetime`, `Decimal`, `UUID` or your own classes, raises a `TypeError`:

```python
from datetime import datetime
from decimal import Decimal

try:
    json.dumps({"created": datetime(2026, 11, 22, 18, 0)})
except TypeError as err:
    print("TypeError:", err)
```

**Output:**

```text
TypeError: Object of type datetime is not JSON serializable
```

The fix is a pair of hooks:

- **`default=`** (on `dumps` / `dump`): a function that receives any object JSON cannot handle and returns something it can.
- **`object_hook=`** (on `loads` / `load`): a function that receives every decoded `dict` and may return a different object, e.g. rebuild your class.

A marker key such as `"__type__"` tells the decoder which dictionaries are really an `Order`. Money is stored as a **string** so a `Decimal` never loses precision by passing through a `float`.

```python
class Order:
    def __init__(self, item: str, total: Decimal, created: datetime):
        self.item = item
        self.total = total
        self.created = created


def encode_custom(obj):
    if isinstance(obj, Order):
        return {"__type__": "Order", "item": obj.item,
                "total": str(obj.total), "created": obj.created.isoformat()}
    if isinstance(obj, datetime):
        return obj.isoformat()
    if isinstance(obj, Decimal):
        return str(obj)
    raise TypeError(f"Type {type(obj).__name__} not serializable")


def decode_custom(dct):
    if dct.get("__type__") == "Order":
        return Order(dct["item"], Decimal(dct["total"]),
                     datetime.fromisoformat(dct["created"]))
    return dct


order = Order("Keyboard", Decimal("4499.99"), datetime(2026, 11, 22, 18, 0))

payload = json.dumps(order, default=encode_custom)
print("JSON    :", payload)

restored = json.loads(payload, object_hook=decode_custom)
print("Restored:", type(restored).__name__, restored.item, restored.total, restored.created)
```

**Output:**

```text
JSON    : {"__type__": "Order", "item": "Keyboard", "total": "4499.99", "created": "2026-11-22T18:00:00"}
Restored: Order Keyboard 4499.99 2026-11-22 18:00:00
```

> 💡 Always `raise TypeError` for types the encoder does not know. Unsupported types then fail loudly instead of being silently dropped or mis-saved.

## Working with Nested JSON

Real API responses are deeply nested, and parts are often missing or `None`. Chaining `[...]` raises `KeyError` / `TypeError` as soon as one level is absent, so chain **`.get()`** with a fallback instead. The `or {}` trick also protects against a key that exists but holds `None`.

```python
data = {"user": {"name": "Rohan", "address": {"city": "Pune"},
                 "orders": [{"id": "A1", "items": ["Mouse", "Pad"]},
                            {"id": "A2", "items": ["Cable"]}]}}

# Safe chained lookup (works even if 'user' or 'address' is missing or None)
user = data.get("user") or {}
city = (user.get("address") or {}).get("city", "Unknown")
print("City:", city)

missing = ({}.get("user") or {}).get("address") or {}
print("Missing user ->", missing.get("city", "Unknown"))

# The unsafe version fails as soon as one level is None
broken = {"user": {"address": None}}
try:
    broken["user"]["address"]["city"]
except TypeError as err:
    print("TypeError:", err)

# Flatten nested lists with a comprehension
all_items = [item for o in user.get("orders", []) for item in o.get("items", [])]
print("All items:", all_items)
```

**Output:**

```text
City: Pune
Missing user -> Unknown
TypeError: 'NoneType' object is not subscriptable
All items: ['Mouse', 'Pad', 'Cable']
```

When you do not know **where** a key lives, a small recursive generator finds it at any depth:

```python
def find_all(obj, target):
    """Yield the value of every key named `target`, at any depth."""
    if isinstance(obj, dict):
        for k, v in obj.items():
            if k == target:
                yield v
            yield from find_all(v, target)
    elif isinstance(obj, list):
        for elem in obj:
            yield from find_all(elem, target)


print(list(find_all(data, "id")))
print(list(find_all(data, "city")))
```

**Output:**

```text
['A1', 'A2']
['Pune']
```

## Validating JSON (Pydantic vs. `jsonschema`)

Parsing only proves the text is *valid JSON*. It does not prove the data has the **shape you expect**. Two popular tools check that:

| Tool | Best for | Result |
|------|----------|--------|
| **Pydantic** (`pip install pydantic`, v2) | Parsing JSON directly into **typed Python objects** with validation | A model instance, or a `ValidationError` |
| **jsonschema** (`pip install jsonschema`) | Checking raw `dict`s against a language-neutral **JSON Schema** | Passes silently, or raises `ValidationError` |

### Pydantic

Declare the shape once as a class; `model_validate_json()` parses *and* validates in a single step. It also converts compatible values (the ISO date string becomes a real `datetime`).

```python
from typing import Optional
from pydantic import BaseModel, Field, ValidationError


class OrderItem(BaseModel):
    order_id: str
    total: float = Field(gt=0)


class UserProfile(BaseModel):
    id: int
    name: str = Field(min_length=2)
    nickname: Optional[str] = None
    created_at: datetime
    orders: list[OrderItem] = []


raw_json_string = """
{"id": 1, "name": "Meera", "created_at": "2026-11-22T09:30:00",
 "orders": [{"order_id": "A1", "total": 499.0}]}
"""

try:
    profile = UserProfile.model_validate_json(raw_json_string)
    print(profile.name, profile.orders[0].total, type(profile.created_at).__name__)
    print(profile.model_dump_json(indent=2, exclude_none=True))
except ValidationError as e:
    print(e.json(indent=2))
```

**Output:**

```text
Meera 499.0 datetime
{
  "id": 1,
  "name": "Meera",
  "created_at": "2026-11-22T09:30:00",
  "orders": [
    {
      "order_id": "A1",
      "total": 499.0
    }
  ]
}
```

Invalid data is rejected with a precise report of **where** and **why**:

```python
bad_json = '{"id": "x", "name": "A", "created_at": "2026-11-22T09:30:00", "orders": [{"order_id": "A1", "total": -5}]}'

try:
    UserProfile.model_validate_json(bad_json)
except ValidationError as e:
    print(f"{e.error_count()} problems found:")
    for problem in e.errors():
        where = ".".join(str(part) for part in problem["loc"])
        print(f"  {where}: {problem['msg']}")
```

**Output:**

```text
3 problems found:
  id: Input should be a valid integer, unable to parse string as an integer
  name: String should have at least 2 characters
  orders.0.total: Input should be greater than 0
```

### jsonschema

Use a schema when the rules must be shared with non-Python systems (or stored next to the data). `validate()` returns `None` on success and raises `ValidationError` on failure.

```python
from jsonschema import validate, ValidationError as SchemaError

schema = {
    "type": "object",
    "required": ["id", "name"],
    "properties": {
        "id": {"type": "integer"},
        "name": {"type": "string", "minLength": 2},
    },
}

validate({"id": 1, "name": "Meera"}, schema)
print("Valid document accepted")

try:
    validate({"id": "1", "name": "Meera"}, schema)
except SchemaError as err:
    print("Rejected:", err.message)
```

**Output:**

```text
Valid document accepted
Rejected: '1' is not of type 'integer'
```

## Debugging & Fixing Parsing Errors (`JSONDecodeError`)

`json.loads()` raises `json.JSONDecodeError` (a subclass of `ValueError`) for text that is not valid JSON. The message tells you what went wrong, and the error object tells you where (`msg`, `lineno`, `colno`, `pos`).

| Error Message | Cause | Fix |
|---------------|-------|-----|
| `Expecting property name enclosed in double quotes` | Single quotes (`{'a': 1}`) or a trailing comma (`{"a": 1,}`) | Use double quotes and remove trailing commas, or use `ast.literal_eval()` for Python dict strings |
| `Expecting value: line 1 column 1` | Empty string / empty file, or an HTML error page returned instead of JSON | Check `if not raw.strip():` and inspect `response.status_code` / `response.text[:200]` |
| `Extra data: line 2 column 1` | Multiple JSON objects, one per line (**JSON Lines** / NDJSON) | Parse line by line: `[json.loads(line) for line in f if line.strip()]` |
| `Unexpected UTF-8 BOM` | A Windows UTF-8 BOM prefix (`\ufeff`) | Open the file with `encoding="utf-8-sig"` |

Here is each error, reproduced:

```python
samples = {
    "single quotes":  "{'a': 1}",
    "trailing comma": '{"a": 1,}',
    "empty string":   "",
    "two objects":    '{"a": 1}\n{"a": 2}',
}

for label, text in samples.items():
    try:
        json.loads(text)
    except json.JSONDecodeError as err:
        print(f"{label:15} -> {err.msg} (line {err.lineno}, col {err.colno})")
```

**Output:**

```text
single quotes   -> Expecting property name enclosed in double quotes (line 1, col 2)
trailing comma  -> Expecting property name enclosed in double quotes (line 1, col 9)
empty string    -> Expecting value (line 1, col 1)
two objects     -> Extra data (line 2, col 1)
```

### Locating the problem

`err.pos` is the character offset of the failure, so slicing a few characters around it shows exactly where the text goes wrong:

```python
raw_text = '{"name": "Asha", "skills": ["Python" "SQL"]}'    # comma missing between list items

try:
    json.loads(raw_text)
except json.JSONDecodeError as err:
    print(f"Error: {err.msg} at line {err.lineno}, col {err.colno}")
    snippet = raw_text[max(0, err.pos - 20): err.pos + 20]
    print(f"Near: {snippet!r}")
```

**Output:**

```text
Error: Expecting ',' delimiter at line 1, col 38
Near: '"skills": ["Python" "SQL"]}'
```

### Two fixes in practice: JSON Lines and the BOM

**JSON Lines** files hold one complete JSON document per line, which is common for logs and large exports because each line can be processed alone. **A BOM** (byte-order mark) is an invisible character that some Windows tools write at the start of a UTF-8 file.

```python
# JSON Lines: one JSON document per line
with open(path("events.jsonl"), "w", encoding="utf-8") as f:
    f.write('{"event": "login", "user": 1}\n{"event": "logout", "user": 1}\n')

with open(path("events.jsonl"), "r", encoding="utf-8") as f:
    events = [json.loads(line) for line in f if line.strip()]
print(events)

# UTF-8 BOM: "utf-8" fails, "utf-8-sig" strips the marker
with open(path("bom.json"), "w", encoding="utf-8-sig") as f:
    f.write('{"ok": true}')

try:
    with open(path("bom.json"), "r", encoding="utf-8") as f:
        json.load(f)
except json.JSONDecodeError as err:
    print("utf-8     ->", err.msg)

with open(path("bom.json"), "r", encoding="utf-8-sig") as f:
    print("utf-8-sig ->", json.load(f))
```

**Output:**

```text
[{'event': 'login', 'user': 1}, {'event': 'logout', 'user': 1}]
utf-8     -> Unexpected UTF-8 BOM (decode using utf-8-sig)
utf-8-sig -> {'ok': True}
```

## Clean Up & Key Takeaways

1. `loads` / `dumps` work with **strings**; `load` / `dump` work with **files**. Use `indent` and `sort_keys` for readable output and `ensure_ascii=False` plus `encoding="utf-8"` for non-English text.
2. A JSON round trip is not lossless: tuples become lists, dictionary keys become strings, and `datetime`, `Decimal` and custom classes need `default=` / `object_hook=`.
3. For nested data, chain `.get()` with `or {}` fallbacks instead of square brackets.
4. Parsing proves the text is valid JSON; **Pydantic** or **jsonschema** prove it has the right shape.
5. Read `JSONDecodeError` carefully: its message, `lineno`, `colno` and `pos` point to the fault.
